# 垃圾回收机制

## 什么是垃圾回收机制

垃圾回收机制（Garbage Collection，简称GC）是JavaScript中使用的内存管理系统的基本组成部分，是为了防止内存泄漏。

JavaScript在创建变量（对象、字符串等）时自动进行了分配内存，并且在不使用它们时会自动释放。内存在不适用的时候就被垃圾回收器自动回收。

## 为什么需要垃圾回收机制

如果没有垃圾回收机制，适时清理不被引用的值并释放相应的内存空间，JavaScript解释器将会消耗完系统中所有可用内存，造成系统崩溃。

程序的运行过程中会申请大量的内存空间，对于一些无用的空间如果不及时清理的话会导致内存溢出（不够用），程序就会崩溃。管理内存是非常复杂的事情，垃圾回收机制就把程序员从复杂的内存管理中解放出来。

## 垃圾回收的核心思路

所谓垃圾回收的核心思想就是清理掉内存中不再被引用的值，通俗地说，就是清理掉内存中没用的值。

## 垃圾回收的两种方式

### 1. 标记清除（Mark-and-Sweep）- JS最常用

标记清除法主要有以下步骤：

1. 给所有变量增加一个标记，如果是进入执行环境（比如申明变量），则标记为"进入环境"，如果是结束执行环境（比如执行完相关函数），则标记为"离开环境"；
2. 去掉"进入环境"的变量标记以及被该变量所引用的变量标记（比如闭包）；
3. 还存在标记的变量即是需要被清理的变量。

原理：
- 标记阶段：垃圾回收器从根对象（如全局对象）开始，遍历所有可达的对象，给这些对象打上标记。
- 清除阶段：遍历堆内存中的所有对象，未被标记的对象被视为垃圾，回收其占用的内存空间。

优点：
- 能够处理循环引用的问题。

### 2. 引用计数（Reference Counting）

引用计数法主要有以下步骤：

1. 申明了一个变量，并且将一个引用类型的值赋值给这个变量，那么这变量的引用就加1；
2. 如果这个变量的值又指向另外一个值，或者说这个变量被重新赋值了，那么以上的引用类型的值的引用次数就减1；
3. 如此一来，该引用类型的值的引用次数即为0，垃圾回收器会在运行的时候清理掉引用次数为0的值并释放相应的内存空间；

原理：每个对象都有一个引用计数，表示有多少个变量或属性引用了这个对象。当一个对象的引用计数变为0时，表示没有变量再使用该对象，此时就可以将其占用的内存释放。

优点：
- 实时性好，一旦对象不再被使用，立即回收。

缺点：
- 无法处理循环引用的问题，即两个对象相互引用但不再被外部访问时，它们的引用计数都不为0，导致无法被回收。

示例：
```javascript
function testGC() {
  var objA = {};
  var objB = {};
  
  // 建立循环引用
  objA.ref = objB;
  objB.ref = objA;
  
  // 此时，即使objA和objB不再被外部访问，它们的引用计数也非0，不会被回收
}

testGC();
// 在某些JavaScript引擎中，objA和objB因为循环引用可能会造成内存泄漏
```

在现代JavaScript引擎中，尤其是使用了标记-清除算法的V8引擎，已经对循环引用有了较好的处理，能够识别并回收这类循环引用的对象，从而减少内存泄漏的风险。

## V8引擎的垃圾回收优化策略

### 分代回收

V8引擎根据对象的生命周期将堆内存分为新生代和老生代两个区域：

1. 新生代（Young Generation）：
   - 存放生命周期较短的对象
   - 采用Scavenge算法（空间复制）
   - 对象晋升条件：经历过一次GC存活或To空间占用超25%

2. 老生代（Old Generation）：
   - 存放生命周期较长的对象
   - 采用标记-清除与标记-整理算法

### 增量标记（Incremental Marking）

将标记过程拆分为多个小步骤，避免长时间阻塞主线程。

### 惰性清理（Lazy Sweeping）

延迟清理未被标记的内存区域，按需执行。

### 并发标记

使用后台线程执行标记任务，不阻塞JS执行。

## 常见的内存泄漏问题

### 1. 意外声明全局变量

```javascript
function setName() {
  name = 'Jake'; // 没有使用var/let/const声明，成为全局变量
}
```

此时变量name会被当做window的属性，即全局对象来处理，只要window本身不被清理就不会消失。

### 2. 定时器未清理

```javascript
let name = 'Jake';
setInterval(() => {
  console.log(name);
}, 100);
```

只要定时器一直运行，回调函数中引用的name就会一直占用内存。

### 3. 使用闭包

```javascript
let outer = function() {
  let name = 'Jake';
  return function() {
    return name;
  };
};
```

内部闭包只要outer函数存在就不能清理name。

### 4. DOM引用未解除

```javascript
let elements = {
  button: document.getElementById('button')
};

document.body.removeChild(elements.button);
// 仍保留elements.button的引用，阻止GC回收
```

## 如何检测和避免内存泄漏

### 检测方法

1. 使用Chrome DevTools的Performance面板录制内存变化
2. 使用Memory面板进行堆快照（Heap Snapshot）对比筛选
3. 检查Detached DOM tree

### 避免方法

1. 及时清理定时器
2. 及时解除DOM引用
3. 避免滥用闭包
4. 减少不必要的全局变量

## WeakMap如何解决内存泄漏

```javascript
const weakMap = new WeakMap();
let domNode = document.getElementById('node');

weakMap.set(domNode, { metadata: 'info' });

domNode = null; // 当DOM节点移除后，WeakMap中的条目自动被GC回收
```

WeakMap的键是弱引用，不计入GC可达性判断，典型应用是存储DOM节点元数据而不影响其生命周期。

## 常见面试题

### 1. JS如何判断对象是否可回收？

答案：可达性标准：从根对象（全局对象、当前函数作用域链、活动执行上下文）出发，遍历所有引用链，不可达对象会被标记回收，与引用计数无关。

### 2. 引用计数为何被淘汰？举例说明循环引用问题

答案：引用计数无法识别循环引用，导致内存泄漏。

```javascript
function createCycle() {
  let objA = { name: 'A' };
  let objB = { name: 'B' };
  
  objA.ref = objB; // objA引用objB
  objB.ref = objA; // objB引用objA
}

createCycle();
// 函数执行后，objA和objB的引用计数永远为1
```

### 3. 闭包一定会导致内存泄漏吗？

答案：否。只有当闭包持续引用不再需要的大对象时才会泄漏。

### 4. 如何手动触发垃圾回收？

答案：浏览器环境（非标准API）：
```javascript
if (typeof window.gc === 'function') {
  window.gc(); // Chrome需启动时加参数：--js-flags="--expose-gc"
}
```

Node.js环境：
```javascript
global.gc(); // 启动时需添加`--expose-gc`参数
```

## 总结

JavaScript的垃圾回收机制通过标记-清除和引用计数两种策略协同工作，以自动管理内存。开发者虽然不需要直接控制内存分配和释放，但了解这些机制有助于写出更高效的代码，避免内存泄漏。在编写代码时，尽量减少不必要的全局变量，及时解除不再使用的对象引用，可以帮助垃圾回收器更高效地工作。
